same bucket is used to store statefile and locking 

it uses a tag based locking one statefile per key 
- When you enable use_lockfile = true in the S3 backend, Terraform creates a lock object in the same S3 bucket where the state file lives.
- This lock object is essentially a small file (e.g., terraform.tfstate.lock) that contains metadata about the lock (who holds it, when it was acquired).
- While the lock file exists, other Terraform processes trying to acquire the lock will fail — preventing concurrent writes.
- Once the operation completes, Terraform deletes the lock file, releasing the lock.
- Tag‑based locking: Terraform uses a unique identifier (a “lock ID” or tag) to mark that a particular state file is currently in use.
- One statefile per key: In S3, each state file is stored as an object, and the object key (like prod/terraform.tfstate) uniquely identifies that state.
- When you run terraform apply, Terraform tries to acquire a lock for that specific key.
- If another process is already holding the lock for the same key, Terraform blocks or fails until the lock is released.
