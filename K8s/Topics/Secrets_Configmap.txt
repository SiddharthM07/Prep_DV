Pods consume configmaps in three ways

env variables
command line args (less common)
configuration file via mounted volumes

If we change the env variable deinfed in our pod k8s will take a rolling restart to update it 
assume we defined a value in configmap and then our pod is refrencing it and if a value which our pod is refrencing is being changed in configmap to get that reflected in pod we need to do rolling update but if we add config map as volume the changes are dynamic 

Note: everything that is inside CM is copied as files on the path when we plug it as volume.
config maps are mounted in as a directory  if we want to attach them as file we need to define them as subpath but the changes will not be dynamic

External Secrets
========================

We use the Secrets Store CSI Driver with AWS provider, allowing pods to fetch secrets dynamically from AWS Secrets Manager using IRSA, eliminating static Kubernetes secrets and improving security.
You create a Kubernetes service account connected to an IAM role.
Pod → IAM Role → AWS Secret Manager

Kubernetes cannot understand AWS secrets by itself.
So we install a helper called:
-->Secrets Store CSI Driver
Think of it like:
Translator between Kubernetes and AWS.

kind: SecretProviderClass
spec:
  provider: aws
  parameters:
    objects: |
      - objectName: "ott-db-secret"
        objectType: "secretsmanager"

insidepod

volumeMounts:
  - name: secrets-store
    mountPath: "/mnt/secrets"
